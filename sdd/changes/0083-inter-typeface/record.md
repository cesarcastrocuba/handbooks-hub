# Change 0083 — One typeface: Inter in every edition and the portal

Implementer Claude; reviewer a different agent; the Owner merges. Branch `feat/inter-typeface`
from main `189b352`. No version bump or tag: it ships with toolkit `0.16.0`, whose tag needs the
Owner's approval.

## Owner decisions (2026-11-26)

The Owner reviewed a sketch of the portal, a book chapter page (light and dark), a phone view and a
print page, and decided:

- keep the colours, callouts and layout as they are, and change only the typeface, in HTML, PDF
  and Word ("lo dejamos como está pero cambiamos letra en todos los formatos html pdf y word": we
  leave it as it is but change the typeface in every format);
- Inter for text and headings ("Quisiera inter para todo": Inter for everything), JetBrains Mono for
  code as before;
- the Word edition embeds the fonts, so a reader without Inter installed still sees it;
- after the first CI preview (PDF 541 → 611 pages at 10 pt), the PDF body text is set at 9.5 pt;
  Word and web sizes are unchanged.

Recorded as `HUB-DEC-045`.

## Changes

- `render_data/fonts/inter/`: the four TTFs, four WOFF2 subsets and `OFL.txt`;
  `render_data/fonts/source-sans3/` and `source-serif4/` are removed.
- `design/tokens.json`: `type.brand`, `type.body` and `type.display` name Inter for web, print and
  Word.
- `design.py`: the web font list, the licence list, the `@font-face` comment and the Quarto font
  variables; `render_resources.py` and `build_staging.py` stage and point Typst at `fonts/inter`;
  `typst-show.typ` names Inter. The PDF body size is 9.5 pt in `typst-show.typ`,
  `handbook-typst.typ` and the `type.body.print_size_pt` token.
- `docx_fonts.py`: Inter's alternate chain is Segoe UI → Calibri → Arial; `embed_fonts` adds the
  packaged TTFs as obfuscated parts (`word/fonts/fontN.odttf`, ISO/IEC 29500-1, 17.8.1) with
  `embedRegular`/`embedBold`/`embedItalic`/`embedBoldItalic`, the font-table relationships, the
  `odttf` content type and `embedTrueTypeFonts`. The font key is a UUID 5 of the file's sha256, so
  the DOCX stays byte-reproducible. `prepare_docx` calls it.
- `docx_pages.py`: the LibreOffice probe no longer aliases Source Sans 3 and Source Serif 4; the
  DOCX names the packaged families directly.
- `render_data/docx/reference.docx` regenerated by `tools/scripts/generate_reference_docx.py`.
- Portal footers link `fonts/inter/OFL.txt`.
- `.github/workflows/ci.yml` (`wheel-install`): the staged portal ships 7 WOFF2 files, not 10.
- Docs: `docs/design.md`, `NOTICE.md`, `template/book/NOTICE.md`, `docs/operations-runbook.md`,
  `docs/decisions.md` (`HUB-DEC-045`), `CHANGELOG.md`.
- Tests: the font pins in `test_design`, `test_design_conformance`, `test_docx_native`,
  `test_build`, `test_numbering_parity`, `test_template` and `test_reading_site`; new
  `test_docx_fonts.py` (every face embedded once, each part de-obfuscates to the packaged file,
  schema order, content type and setting, idempotent, a package without content types is left
  alone).

## Evidence

Run on 2026-11-26 in the hub venv (`requirements-dev.txt`), Python 3.12, LibreOffice and Quarto of
the host:

- `make check`: 627 tests, OK, none skipped, in a venv that also has Playwright 1.60.0 and
  Chromium; without them the five browser tests skip (review comment 7203474309).
  `VERIFY: 5 check(s), 0 problem(s)`.
- Embedded fonts read by a second consumer: a Markdown sample converted with `quarto pandoc` and the
  regenerated reference, then `prepare_docx`, then `soffice --convert-to pdf` on a host where
  `fc-list` lists neither Inter nor JetBrains Mono. `pdffonts` of the result lists Inter-Regular,
  Inter-Bold, Inter-Italic and JetBrainsMono-Regular, all embedded: LibreOffice de-obfuscated the
  DOCX font parts with their keys. The sample DOCX is 1,219,470 bytes, nearly all of it fonts.
- `test_figure_place.LibreOfficeTests.test_a_figure_that_nearly_fits_is_scaled_in_place` depends
  on the text metrics in front of the figure. With Inter its fixture (228 pt tall figure) no longer
  left a gap to scale into. A probe of fills 3-6 and heights 2600000-4250000 EMU found the gap
  rule scaling the figure at fill 5 for 3650000-4100000 EMU except 3900000; the fixture now uses
  3800000 (299 pt). The result was the same in three repeated probes.
- `test_reading_site` failed once in a first run of the suite and passed in the three later runs,
  including `make check`; the failure was not reproduced and its output was not kept.

Not run locally: a full build of the Solutions Architecture Handbook. The CI `edition-preview` job
builds it with this toolkit; its page counts and the layout audit of change `0081` are added to the
pull request from that artifact.
