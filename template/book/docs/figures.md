# Figures

Keep original images under manuscript/images/ and use a path relative to the chapter. The example
chapter includes section-structure.svg, an original diagram supplied with this template.

```markdown
![A short caption.](../images/section-structure.svg){#fig-section-structure fig-alt="Describe the relationship shown, not the file name." width="90%"}

See @fig-section-structure.
```

Use an explicit fig- identifier, a meaningful caption and alt text. Keep labels unique across the
book. SVG is suitable for diagrams; PNG and JPEG suit raster images. Use local files: builds are
reproducible and do not fetch remote images. For Word compatibility, keep SVGs simple (basic shapes,
paths and text); avoid scripts, foreignObject, external fonts/styles/images, and interactive SVG.
Complex SVG features may render differently in Word and LibreOffice. Prefer PNG when a diagram
cannot be expressed portably. Size the figure with a relative width; keep text readable in print.

HTML provides a native List of Figures; PDF has its own list and DOCX has a native field with cached
linked titles. Word can update that field for page numbers. book.md keeps the caption and omits the
image binary, so the Markdown edition remains a single file. Inspect every edition before release.

The supplied figure is generated by the hub's generate_template_figure.py from original drawing
source and the shared palette. Its SVG coordinates are illustration geometry; the renderer's UI
sizes and timing remain centralized in the design contract. You do not need that generator to
build or replace the figure in a copied book.
